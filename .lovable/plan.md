# Two design proposals (no code yet)

## Problem 1 — Randomisation engines converge on the brand

### What the code actually does today

`random_connection` and `wrong_room` are already in `BRIEF_ISOLATED_ENGINES`. They do **not** receive the brand name or category. They receive one sentence: an abstracted strategic opportunity, produced by `abstractStrategicOpportunity()` from the Stage 1 brief.

So the falcon did not come from the brand name being visible. It came from two other leaks:

1. **Residual semantic leak in the abstract sentence.** Stripping the word "Jaguar" does not strip "a heritage performance marque re-entering an electric premium segment". That sentence still points hard at predator/speed/British-luxury space. The model then "randomly" picks a falcon.
2. **Self-sourced randomness.** The stimulus is *generated by the same model that just read the opportunity sentence*. Asking a language model for a random object samples from what is currently activated in its context. This is a mechanism problem, not a wording problem.

### Proposed design — externally sourced stimulus, selected before the model sees anything

**A. A real stimulus corpus, committed to the repo.**
A static dataset of ~600–1000 concrete stimuli, each a specific thing with rich properties, not a category. Structured, not a flat word list:

```
{ id, name, domain, properties[], mechanics[], failure_modes[] }
e.g. { name: "cold-forged bicycle spoke", domain: "materials",
       properties: ["tensioned only in one axis", "fails suddenly not gradually"] }
```

Domains are tagged (materials, biology, bureaucracy, sport, ritual, logistics, weather, music, crime, medicine, childhood, machinery…). Curated once, versioned in git, no runtime dependency.

**B. Selection happens in code, not in the model.**
Seeded PRNG in `loc.functions.ts`, seed = `sessionId + engine + attempt`. Deterministic per attempt (so retries are reproducible and a retry deliberately draws a *different* stimulus), random with respect to the brand.

**C. Semantic-distance rejection sampling.**
Before the draw is accepted, compute similarity between the stimulus record and the brand + category + abstract opportunity, and reject anything above a threshold — redraw up to N times. Two options:
- *Cheap:* token/lemma overlap plus a hand-maintained banned-adjacency map (`jaguar → cat, predator, falcon, hunt, big-cat, prowl…`). No API cost, catches the obvious cases, misses the subtle ones.
- *Proper:* embeddings via the AI gateway, cosine distance, reject above ~0.25. One extra call per LOC run (embed brand context once, corpus vectors precomputed at build time and committed). Catches falcon/jaguar, which lemma overlap would not.

Recommendation: build the embedding version, keep the banned-adjacency map as a cheap pre-filter.

**D. Hard-fix the abstraction leak.**
`abstractStrategicOpportunity()` gets a stricter contract: output must be a *structural* opportunity sentence — no material, no heritage, no era, no sensory register, no animal, no country. "A brand whose historic proof point is no longer the thing buyers are choosing on." Add a code-side rejection check against a leak lexicon before the sentence is used.

**E. Prompt change is the last mile, not the fix.**
The engine prompt changes from "generate a random stimulus" to "here is your stimulus: X. You may not change it, and you may not reject it. Explore it exhaustively before you touch the opportunity." Rejecting the assigned stimulus becomes an output-validation failure, not a model choice.

### Tradeoffs, stated honestly

- **Corpus curation is real work and it is a bias surface.** Whoever writes the 800 entries decides the whole engine's imaginative range. It needs periodic expansion or every brand starts drawing from the same well and outputs converge platform-wide instead of brand-wise. Mitigation: draw domain first (uniform over domains), then item within domain; log draws so repetition across sessions is visible.
- **Forced stimuli reduce hit rate.** Today the model picks something it can already connect, which is exactly the bug — but it does mean most outputs "work". Assigned-random will produce a meaningfully higher share of strained, unusable collisions. That is the intended cost of divergence, but it argues for drawing 3 stimuli and generating 3 candidates per randomisation engine, then keeping the best — more tokens, more time.
- **Embeddings add a dependency and a failure mode** in a pipeline that has had reliability problems. Needs a fallback: if embedding fails, fall back to the lexical filter rather than blocking the engine.
- **Determinism vs. genuine novelty.** Seeded draws are reproducible and debuggable but a repeated run of the same session yields the same stimulus. Acceptable; the retry path increments the attempt counter.
- **`wrong_room` needs its own corpus.** Industries/worlds, not objects — same mechanism, separate table, same distance filter.

## Problem 2 — Stage 11 treats attackability as fatal

### What the code actually does today

Stage 11 runs five pressure tests, each returning HOLDS / WOBBLES / CRACKS, and the verdict logic in the prompt is: **any CRACKS → ELIMINATE**. `filterValidatedFromStage11()` then physically removes eliminated propositions before Stage 12 ever sees them. Test 1 is "Competitive Counter-Proposition" — construct the strongest competitor counter; CRACKS if the counter is stronger.

That test is doing two unrelated jobs at once. "A competitor could say something stronger" and "this proposition is untrue or incoherent" both come out as CRACKS, and both are equally fatal. Jaguar's boldest line died on the first, framed as the second.

### Proposed redesign — split the axis, and make only one of them fatal

**Fatal tier (automatic elimination, unchanged severity):**
- **T1 Factual falsity** — the claim is contradicted by evidence the brand cannot dispute (current Test 3, tightened: requires a *named* contradicting evidence vector, no speculation).
- **T2 Logical incoherence** — the line does not mean what it claims, collapses under a plain reading, or the descriptor contradicts the line.
- **T3 Permission failure** — the brand has no credible right to say it today.
- **T4 Forbidden Zone violation** — inevitable CMM zone breach (current Test 4 at CRACKS only).

**Non-fatal tier (flag, ranked, forwarded to human):**
- **T5 Competitive counter-vulnerability** — a competitor can construct a strong counter. Now returns `EXPOSED / CONTESTED / DEFENDED` plus the counter line verbatim.
- **T6 Time decay** — becomes a flag with a stated horizon rather than an eliminator, since near-term category absorption is genuine information but not a truth failure.
- **T7 Interpretation drift** — currently folded into Test 4's WOBBLE; separated out as a guard-rail requirement.

**The new discriminator.** Before T5 can be scored, the model must classify the counter it constructed:
- *Counter exposes an untruth* → escalate to the fatal tier as T1/T2 and eliminate.
- *Counter competes for the same territory* → EXPOSED flag, not elimination.

That single classification step is the whole redesign. Everything else is bookkeeping around it.

**Downstream changes.**
- `filterValidatedFromStage11()` stops removing propositions eliminated on competitive grounds; it only removes fatal-tier failures.
- Stage 11 output gains a machine-readable block per proposition: `FATAL: none | T1..T4` and `FLAGS: EXPOSED(counter="…") | DECAY(horizon=…) | DRIFT(guardrail="…")`.
- Stage 12 receives survivors *with* their flags, plus an explicit instruction that an EXPOSED flag is a boldness signal to be weighed, not a defect to be avoided.
- Checkpoint D (existing human gate) surfaces flagged propositions to you with the constructed counter shown, so the "is this bold or is this broken" call is made by a person with the evidence in front of them.

### Tradeoffs, stated honestly

- **More propositions reach Stage 12.** The set grows, dilution risk rises, and Stage 12 is currently tuned for a pre-filtered set. It will need its own selection guidance updated in the same pass, or the change just moves the failure downstream.
- **The classification step is a model judgement, and it is the load-bearing one.** If the model mislabels "exposes an untruth" as "competes for territory", genuinely broken propositions survive. Mitigation: require the model to quote the specific falsity when it escalates, and default to *fatal* when the classification is uncertain — bias toward the current behaviour, not away from it.
- **Human load increases.** Checkpoint D gets more to read. That is the explicit trade: the system stops making an unrecoverable judgement call and hands you a recoverable one.
- **Historical comparability breaks.** Sessions run before and after this change are not comparable on validated-set size. Worth stamping a Stage 11 logic version onto the session record.
- **Bold and attackable is still sometimes just wrong.** This redesign does not make the system better at telling them apart — it stops the system from *pretending* it can, and routes the ambiguous cases to you.
