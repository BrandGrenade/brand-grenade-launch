
- Partner Hub events are queued by database triggers on Room status/document/sign-off changes into a private outbox and sent by a server sender; why: fires identically for every stage and model without touching stage logic.
- Score-line parsers must accept the cleaned form "N/10 (revised from M/10)." and be tested on text passed through stripDocumentMetadata; why: the cleaner rewrites review markers before parsing, and a raw-text-only test let Jaguar downloads break twice.
- Keep the public methodology headline in platform-metrics separate from the audited register count; why: public copy updates must not change the underlying inventory or other platform metrics.
- Repository visitor passwords are bcrypt-only (no scrypt fallback, no readable column); why: readable passwords must never be stored or shown — admins reset, never view.
- Run-to-client links (bg_client_id/engagement_id/link_status on Room run tables) are set only by the database: Hub tags resolved via bg_external_ids, inheritance via bg_source_id/session_id, or admin bg_admin_link_run; never by brand name; why: signed-in users cannot forge links and every Room behaves the same. Tests: scripts/test-bg-foundation.sql (self-rolling-back).
- Run versions and locks are enforced by the `bg_version_and_lock` trigger on sessions/briefing_room_workspaces (cleared or overwritten outputs saved to run_output_versions; locked runs refuse content changes); app code only passes `version_reason`/`version_actor` and pre-checks the lock; why: every retry path, old or new, is covered identically.
- Stages 9/10/11/13 return a trailing `<<<STRUCTURED_JSON … >>>` block in the same call; it is split off before saving (text unchanged), validated in `src/lib/structured-output.ts`, stored in `stage_N_structured` (failures in `stage_N_structured_error`); why: machine-readable records without changing text outputs, documents or parsers.
- Diagnostic runs (`sessions.run_mode`) stop after Stage 13; the `bg_version_and_lock` trigger sets `diagnostic_status` (complete/partial) and locks them; why: one database rule decides completeness for every path.
- Every update that clears a versioned output must pass `version_actor` from the signed-in user; enforced by `src/lib/retry-actor-coverage.test.ts`; why: every rerun records who triggered it.
- Deal briefs (`sessions.brief_type='deal'`, `deal_*` columns, DB-checked and immutable after Stage 1) are framed by appending a `[DEAL CONTEXT]` block in `prepareCall` (claude.server.ts) for Stages 1–13 only; why: one place frames every stage, retry and model without touching stage prompts, and Campaign runs get no block. Tests: scripts/test-t1-deal.sql.
